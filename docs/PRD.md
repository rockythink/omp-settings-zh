# omp-settings-zh 产品需求文档

- 状态：18.6.4 实现与验证
- 基线版本：OMP 18.6.0
- 文档日期：2026-10-04

## 1. 背景

OMP 的 `/settings` 面板由领域设置注册表驱动，包含大量影响模型、上下文、工具、任务、安全和界面的选项。中文用户能够操作英文界面，但容易忽略说明中的副作用、风险警告和生效条件。

维护完整中文分支会复制上游功能代码和发布责任。本项目通过独立 Extension 跟随官方版本，避免承担分支与构建链同步。

本项目在不脱离官方 OMP 的前提下，让原生 `/settings` 设置文案显示为简体中文，并通过插件入口提供官方 Stats 网页的中英文显示切换。

## 2. 目标用户

主要用户：

- 使用官方 OMP 的简体中文开发者；
- 能理解命令、配置键和技术专有名词，但希望降低设置说明阅读成本；
- 希望及时获得 OMP 官方更新，不愿切换到第三方完整分支。

次要用户：

- 希望贡献中文翻译或维护术语一致性的社区成员；
- 希望参考本项目为其他语言制作设置翻译包的 OMP 用户。

## 3. 产品目标

### G1：降低设置理解成本

用户打开原生 `/settings` 后，设置名称、说明、风险警告和有限选项优先显示简体中文；页签、分组标题及硬编码操作提示保留官方原文。

输入 `/` 时，85 个内置命令及别名的补全说明、实时状态和技能数量显示中文。命令名、参数提示、匹配排序、插入与执行保持官方行为；不翻译第三方技能／扩展说明或命令参数、文件补全。

### G2：不影响官方更新

插件不得复制或替换 OMP 业务逻辑。用户继续安装和运行官方 OMP；Stats 在原官方监听器注入显示脚本，不增加代理服务，统计、API 与评估由实际官方 CLI 负责。

### G3：兼容性可见

每个 OMP 版本下的翻译覆盖率和兼容状态应可检测。新增设置不得因为没有翻译而消失。

### G4：可社区维护

翻译数据、术语规范、检查脚本和贡献流程应公开、可审查、可自动验证。

## 4. 非目标

首个版本不承担：

- OMP 全局 TUI 汉化；
- CLI `--help` 和错误消息汉化；
- 系统提示词、工具描述、Agent 角色或文档汉化；
- 中文命令别名；
- 模型输出语言控制；
- 配置值、路径、环境变量或程序标识符翻译；
- 在线机器翻译；
- OMP 分支、二进制重打包或自动补丁。

## 5. 核心用户流程

### 5.1 安装

1. 用户使用 OMP 原生 `plugin install` 或 `plugin link` 安装插件。
2. OMP 验证插件入口并记录启用状态。
3. 下一次启动会话时插件自动加载。

### 5.2 查看和修改设置

1. 用户照常输入 `/settings`。
2. OMP 打开官方设置面板。
3. 插件已在面板构建前覆盖显示元数据。
4. 用户看到中文设置名称、说明和静态选项，页签与分组保持官方原文。
5. 用户通过官方控件修改设置。
6. OMP 使用原有逻辑验证并保存配置。

### 5.3 遇到上游新增设置

1. 插件识别到官方 Schema 中存在未收录路径。
2. 未收录设置保留官方英文文案。
3. 已收录设置继续显示中文。
4. 兼容报告列出未翻译路径，供维护者补充。

### 5.4 遇到不兼容版本

1. 插件启动时检测所需导出、对象结构和可写性。
2. 任一关键前置条件不满足时，插件不应用任何翻译。
3. OMP 继续以官方英文界面运行。
4. 用户收到一次明确、可操作的兼容性提示。

### 5.5 Stats 网页语言

1. 插件正常安装验证时默认生成可撤销 PATH 启动器；本地 link 的首次扩展加载同样自动安装。新终端直接 `omp stats` 执行实际官方 CLI并打开一次中文网页，不需要 Stats 启用命令。
2. 顶部中文 / English 即时切换；首次默认中文，同 origin 跨刷新、路由与服务重启保留选择。
3. 非 Stats、JSON、summary、help 直接官方执行；Web 的 argv、cwd、Profile、stdio、port/host、浏览器打开与独立评估保持。Bun 启动预加载在同一监听器注入脚本，不增加第二服务或地址；已有 BUN_OPTIONS 保留。
4. 仅翻译识别的 DOM 文案，不翻译数据、标识、错误或 canvas。原 handler 先执行，API/SSE、授权拒绝、错误、Host/Origin、方法与 CORS 保持；服务身份头不作为权限判断。
5. Ctrl+C 或退出关闭服务与临时资源；默认安装幂等，正常插件卸载自动撤销自有启动器与 PATH 块，dry-run 不修改。所有权预检保护原 OMP 与无关配置。
6. 会话 `/stats` 不接管。同数据目录下两入口均统计多个项目与会话；会话评估绑定当前会话，CLI 独立。

## 6. 功能需求

### FR-01：原生设置面板复用

插件必须继续使用内置 `/settings` 命令及官方 `SettingsSelectorComponent`，不得注册同名命令或复制一套设置编辑器。

### FR-02：设置文案覆盖

插件必须能够按稳定的设置路径覆盖以下字段：

- `ui.label`
- `ui.description`
- `ui.warning`
- `ui.options[].label`
- `ui.options[].description`

翻译记录不得修改选项的 `value`。

### FR-03：保留原生页签和分组

设置面板继续只汉化设置项；18.4.4 适配时已验证页签/分组模块的磁盘副本不能修改编译宿主。不得修改分组标识或排序，不得用独立副本冒充原生汉化；上游提供稳定接口后再扩展设置面板范围。

### FR-04：英文回退

未收录设置项或选项保留官方原文。动态说明无法按已复核模板匹配时保留其当前原文。缺失翻译不得隐藏设置或改变排序。

### FR-05：兼容性预检

应用翻译前必须一次性验证：

- 所需模块可以解析；
- 所需导出存在；
- Schema 和元数据结构符合预期；
- 待修改对象和属性可写；
- 翻译中的设置路径和选项值可以与当前 Schema 匹配。

关键检查失败时必须整体停止应用，避免部分中文、部分损坏的状态。

### FR-06：幂等性

同一进程内重复加载或重新执行应用函数，不得重复拼接文字、改变排序或产生不同结果。

### FR-07：覆盖率报告

项目必须提供开发期检查命令，输出至少包括：

- 当前含 UI 元数据的设置总数；
- 已翻译设置数；
- 完整翻译数；
- 部分翻译数；
- 未翻译设置路径；
- 翻译表中已被上游删除的路径；
- 选项值不匹配项。

运行时默认不打扰用户；仅在不兼容或翻译应用失败时通知。

### FR-08：设置汉化离线与 Stats 网络边界

设置汉化不得访问网络、调用 LLM 或发送遥测，译文随插件发布，不在线翻译。Stats 只增加原服务上的同源脚本请求，复用官方数据与评估，不新增遥测或改变原权限规则；网页切换不触发评估/付费请求。

### FR-09：保留敏感设置语义

设置翻译层不得读取、记录或展示被标记为凭据或秘密的当前值，只接触 Schema 元数据；Stats 的认证与评估仍由官方实现管理。

### FR-10：可卸载

通过 OMP 原生插件管理卸载或禁用后，下一次进程启动必须恢复完整官方英文界面，不修改用户配置文件。

### FR-11：运行中语言切换

- `/settings-language` 打开原版与简体中文选择器；`zh` / `en` 参数直接选择模式。
- 设置与内置命令补全汉化效果可即时挂载或撤销，无需重启；切换后重新打开原生面板或补全列表。
- 撤销恢复原始值和 getter 描述符，不修改配置值；语言选择只保留在当前进程。
- 主会话管理共享汉化，子会话不能干扰；主会话关闭时清理自己的修改。
- 原生插件管理的实时卸载不在本轮范围，`/reload-plugins` 不等于卸载已加载 Extension。

## 7. 翻译范围和优先级

P0：

- 所有具有 UI 元数据的设置名称与说明；
- 所有风险警告；
- 所有静态选项名称与说明。

P1：

- 设置面板中由官方源码硬编码、但不属于 Schema 的搜索提示和按键提示；仅在上游提供稳定本地化接口后实施。

明确不翻译：

- 主题名、模型名、提供商名；
- 命令名和配置键；
- 路径、URL、环境变量；
- 工具名、协议名、代码标识符；
- 作为程序逻辑值使用的字符串。

## 8. 质量要求

### QR-01：行为零变化

启用前后，除显示文本外，设置路径、当前值、可选值、默认值、条件显示、排序和保存结果必须一致。

### QR-02：启动安全

插件加载失败不得阻止 OMP 启动。兼容失败必须失败关闭并保留英文。

### QR-03：性能

每次从原版挂载中文时线性构建 Mutation Plan；重复选择中文不重复挂载。静态说明不在渲染时查表；动态快捷键说明只读取原始 getter 并填充少量占位符，不复制完整设置面板。

### QR-04：可维护性

业务逻辑、OMP 适配层、翻译数据和验证脚本必须分离。翻译贡献不应要求理解 TUI 实现。
维护必须将 Settings、Commands、Stats 分开审查和报告。Commands 的完整静态覆盖/漂移检查纳入 `bun run check`，并独立核验动态状态和补全接口；锁定依赖检查不替代新宿主的真实编译版交互。任何一部分缺失验证都不能按三部分通过发布。

### QR-05：可审查性

翻译数据必须是确定性的文本文件。自动生成内容必须可重建，并在提交中保留来源说明。

## 9. 验收标准

可发布版本必须满足与其已声明范围对应的验收：

1. 使用官方 OMP 基线版本启动成功。
2. 输入 `/settings` 后仍打开官方设置面板，而非插件自建面板。
3. P0 范围内翻译覆盖率达到 100%。
4. 修改布尔、枚举、数字、文本、多选和凭据类设置的行为与未安装插件时一致。
5. 搜索既能命中中文设置名称，也不破坏官方设置路径和英文回退项。
6. 模拟新增设置时，该项显示英文且其余翻译正常。
7. 模拟删除设置和选项变化时，检查命令准确报告漂移。
8. 模拟关键导出缺失或对象冻结时，插件不应用任何翻译，OMP 保持可用。
9. 设置汉化无网络请求与配置值采集；Stats 不增加第二监听器，除同源语言脚本外仅有官方行为，无额外遥测。
10. 本地插件链接、原生面板加载、中文搜索、编辑及同进程语言切换经过真实编译版验证；原生禁用/卸载遵循下一次启动生效的宿主生命周期。
11. 新 shell 直接 `omp stats` 经真实编译版与浏览器验证：单监听器、默认中文/English、刷新/路由/同地址重启、数据/API/SSE与原授权、窄屏、原参数与JSON/summary、退出、默认安装及卸载；普通验证不触发付费评估。

## 10. 发布边界

### 18.6.2

- 将旧会话替代入口切换为直接 `omp stats` 的可撤销 PATH 启动器；运行实际官方 CLI，不固定另一份 Stats 运行时；
- 保留 argv、cwd、Profile、输出、数据范围与 CLI 评估；以 Bun 预加载在原 Stats 服务同端口注入 JS，删除代理与浏览器打开器替换；
- 验证原命令、语言切换、参数、退出、安装/卸载与稳定安装包路径；已发布 18.6.1 不覆盖。

### 18.6.1

- 插件增量版，实际宿主与官方 Stats 基线仍为 18.6.0，保留 v18.6.0 标签；
- 提供 `/stats-zh` 与网页中文 / English 按钮，保持官方 API、计算、付费确认与原始数据；
- 验证回环代理安全、SSE、语言切换/刷新/路由、窄屏及服务生命周期。

### 18.6.0

- 设置注册表、原文哈希和静态选项无漂移，复核并保留 398 项既有译文；
- 同步依赖、兼容基线与版本说明，兼容层行为保持不变；
- 通过完整自动检查及官方编译版的中文搜索、原生设置编辑和同进程中英文切换验证。

### 18.5.1

- 设置译文覆盖更新为 398 项，新增 `archive.enabled`；
- Archive 保留英文名称，说明其为 Agent 在 eval 中使用的只读历史浏览能力，不译为归档操作；
- 其余 397 项原文哈希与选项无漂移，兼容层行为保持不变。

### 18.5.0

- 设置译文覆盖更新为 397 项，补充 Advisor 审查模式、审查间隔、artifact 文件上限和子 Agent 完成度探测；
- 复核上游变更设置及全量既有译文，按实际控制对象、生效条件、回退和副作用修正语义误译；
- 支持当前 OMP 对 GitHub/npm 插件的按名称更新命令。

### 18.4.6

- 插件版本与目标 OMP 稳定版对齐，旧版本与标签保留；
- 完成 393 项设置名称、说明、警告和静态选项翻译，不翻译页签/分组标题；
- 提供汉化效果热挂载/撤销与语言快捷命令；
- 保持本地链接、GitHub 安装方式及覆盖、漂移、行为契约和真实 TUI 验证流程。
- 上游无设置变更时复用译文，但仍通过兼容和真实界面检查后更新版本与说明；有变更时先补译或复核。

### 后续版本

- 跟随上游 Schema 变化补充翻译；
- 推动 OMP 提供正式设置本地化注册 API；
- 官方 API 可用后移除内部对象修改；
- 在不扩大核心边界的前提下评估其他语言包。

## 11. 成功指标

项目不内置遥测。通过以下公开、非侵入指标判断：

- 发布版本对目标 OMP 版本的 P0 翻译覆盖率；
- 上游发布后兼容检查恢复通过所需时间；
- 与误译、设置行为变化或兼容失败相关的 Issue 数量；
- 社区翻译贡献的合并效率。
